## 2. 폰↔차 계약

두 앱은 **연결 하나**로만 만난다. 구현은 `poc/shared` 한 곳에 있다.

### 2.1 전송 계층

실차에서 폰을 USB 포트에 꽂았을 때 어느 경로가 열리는지는 Pleos 회신에 달려 있다. 그래서 **메시지와 전송을 분리**해 어느 경로든 앱 로직이 같다.

| 경로 | 생기는 것 | 구현 | 확인 |
|---|---|---|---|
| TCP (에뮬레이터·Wi-Fi·USB 테더링) | IP 소켓 | `TcpTransport` | 에뮬레이터 경로만 확인. 폰 → Mac(`adb forward` 또는 콘솔 `redir`) → 차 `10.0.2.2:8080` |
| USB 액세서리 모드(AOA) | 바이트 파이프(bulk), IP 없음 | 차 `UsbHostLink`(`UsbManager` host API), 폰 `UsbAccessoryLink`(`USB_ACCESSORY_ATTACHED` + `openAccessory`) | 미확인. Pleos가 서드파티 앱에 USB host를 열어 준 경우에만 쓸 수 있다 |
| ADB 포워딩 | Mac 중계 | 개발·데모 전용 | 실차와 무관 |

```kotlin
interface Transport { val input: InputStream; val output: OutputStream; fun close() }
```

연결 방향은 항상 **차 → 폰**(폰이 listen, 차가 connect). 에뮬레이터 NAT에서 바깥으로 나가는 접속만 되고, 테더링에서도 폰이 게이트웨이라 자연스럽다. AOA는 USB 호스트(차)가 여는 구조라 방향 개념이 없고 메시지는 대칭이다. 차가 폰을 찾는 순서는 3.6절.

### 2.2 메시지

전송 위에 길이 접두 프레임을 얹는다. 연결 하나로 **양방향**.

```
type(1B) | length(4B, big-endian) | payload
```

| type | 이름 | 방향 | payload | 규칙 |
|---|---|---|---|---|
| 0x01 | `HELLO` | 양방향, 연결 직후 1회 | JSON `{"v":1,"role":"phone"\|"car","screen":[w,h],"now":epoch_ms}` | `v`가 다르면 끊는다. `now`는 보낸 쪽 시계(LIGHT `ts` 보정용, 없으면 보정 없음). HELLO 를 받은 쪽은 자기 LIGHT 를 한 번 보낸다 |
| 0x02 | `FRAME` | 폰 → 차 | JPEG 바이트 | 긴 변 ≤ 1200px, ≤ 15fps. 폰은 **최신 프레임만** 보낸다(쓰는 중이면 건너뜀). 상한 1MB |
| 0x03 | `LIGHT` | 양방향 | JSON `LightingParams`(2.3절) | 받은 값이 내 값보다 최신(`supersedes`)일 때만 적용. `src`가 자기 것이면 무시. 받은 값은 자기 UI에만 반영하고 되돌려 보내지 않는다. 상한 4KB |
| 0x04 | `PING` | 양방향 | 없음 | 5초마다. 15초 무수신이면 끊고, 차가 2초 뒤 재접속 |
| 0x05 | `STATUS` | 폰 → 차 | JSON `{"v":1,"visible":true,"stopped":false,"reason":null}` | 공유 상태. `visible=false` 는 "앱 하나만 공유"의 그 앱이 가려짐(검은 프레임), `stopped=true` 는 공유 끝남(`reason` "user"\|"projection"). HELLO 를 받을 때 한 번, 바뀔 때마다 보낸다. 세션은 닫기 전에 큐를 300ms 까지 비운다 |
| 0x06 | `STATE` | 양방향 | JSON `{"v":1,"ambientLinked":true,"fullLight":false,"dialColor":false,"theme":"black"\|"greige"\|"navy","scenes":[사용자 프리셋],"src":"car"\|"phone"}` | 조명 값 말고 두 앱이 같이 보는 스튜디오 앱 상태(차량 제어 값이 아님). **차가 기준**: 차는 HELLO 를 받으면 한 번, 바뀔 때마다 보낸다. 폰은 사용자가 바꾼 순간에만 보내고 차는 `scenes` 를 뺀 네 값만 받는다. 받은 값은 되돌려 보내지 않는다. 상한 64KB. 모르는 테마는 기본값(`black`) |
| 0x07 | `COMMAND` | 폰 → 차 | JSON `{"v":1,"cmd":"scene.apply"\|"scene.save"\|"scene.delete","id":프리셋 id\|null}` | 프리셋은 차가 저장하고 실내등·독서등도 차가 다루므로 폰은 부탁만 한다. `scene.apply` 는 차 패널에서 누른 것과 같은 경로. 결과는 LIGHT·STATE 로 돌아온다 |

상수(포트 8080, type, 주기, 상한)는 `Protocol.kt`, 프레임 읽기·쓰기는 `MessageCodec.kt`, 세션(HELLO 교환·PING·무수신 끊기·시계 보정)은 `LinkSession.kt`.

### 2.3 조명 값 (`LightingParams`)

```json
{"v":1,"kelvin":3500,"level":0.8,"preset":null,"src":"phone","ts":1731000000000}
```

| 필드 | 타입·범위 | 의미 |
|---|---|---|
| `kelvin` | Int 2700~8000 (기본 7000, 푸른기 도는 흰색) | 색온도. `preset`이 null일 때 적용. 화면에서는 흰 빛 톤 칩 셋(3500K 따뜻한 흰색·5000K 자연광·7000K 푸른 흰색)으로 고르고, 사이 값은 차 다이얼 1칸 250K, 폰 알림·플로팅 버튼 300K |
| `level` | Float 0.0~1.0 (기본 0.6) | 밝기. 다이얼 1칸 0.05, 플로팅 버튼 0.1 |
| `preset` | null \| `"#RRGGBB"` \| `"cyan"` \| `"blue"` \| `"purple"` | 무드 색. 색상환·헥사 입력으로 고른 색은 `"#RRGGBB"`(대문자), 이름 셋은 기본 프리셋용. null이면 색온도 모드. 밝기(`level`)는 어느 쪽이든 그 색에 걸린다 |
| `src` | `"phone"` \| `"car"` | 보낸 쪽 |
| `ts` | epoch ms | 사용자가 이 값을 **마지막으로 바꾼 시각**(0 = 한 번도 안 바꾼 기본값). 어느 쪽 값을 따를지는 3.3절 |

범위 밖 값은 경계로, 모르는 `preset`은 null로 맞춘다(`normalized`). `v`가 다른 JSON은 버린다.

### 2.4 색 변환

- 켈빈 → ARGB는 흑체 복사 근사식(Tanner Helland) **구현 하나**(`ColorTemp.kelvinToArgb`)를 양쪽이 쓴다. 링라이트, 폰 미리보기, `setAmbientLightBrightnessColor`가 같은 값을 받는다.
- 참고값(근사식 실제 출력): 2700K ≈ (255,167,87), 4000K ≈ (255,206,166), 6500K ≈ (255,254,250), 7000K ≈ (243,242,255), 8000K ≈ (221,230,255).
- 이름 있는 무드 색은 상수(`MOOD_COLORS`): 시안 `#00E5FF`, 블루 `#2F6BFF`, 퍼플 `#B04DFF`.
- 헥사는 `"#RRGGBB"`·`"RRGGBB"`·`"#RGB"`를 읽고(`parseHex`) 주고받을 때는 `"#RRGGBB"` 대문자로 쓴다(`toHex`). 색상환은 색상·채도 좌표를 `hsvToArgb`·`argbToHsv`로 바꾼다.
- 실내등·독서등은 켜고 끄기만 되므로 색온도 대상이 아니다.

## 3. 동작 규칙

### 3.1 정차 게이트

- 기어는 AAOS Car API `CarPropertyManager`의 `GEAR_SELECTION`으로 읽는다(Pleos Vehicle SDK에 기어 API가 없다). 권한 `android.car.permission.CAR_POWERTRAIN`.
- P·N이면 사용 가능, 그 밖이면 불가, 아직 못 읽었으면 "차량 상태 확인 중".
- P·N이 아닌 기어를 **한 번이라도** 보면 조명을 먼저 원래 값으로 되돌리고(`restoreNow`), 경고를 3초 띄운 뒤 종료한다. 그 사이 P로 돌아와도 되살리지 않는다.
- 실행 시점에 이미 D·R이면 아무것도 켜지 않은 채 같은 경로로 종료한다(주행 중 실행 차단). 기어를 읽지 못해도 종료한다.
- 감시는 Compose가 아니라 액티비티의 `lifecycleScope`에서 한다. D·N에서는 Pleos가 주행 최적화(DO) 미선언 앱을 가려 `onStop`이 오고, 그러면 Compose 재구성이 멈추기 때문이다.
- 폰 연결과 조명 설정은 사용 가능한 동안만 한다.

### 3.2 조명 원래 값과 복원

- 시작할 때 지원 범위(`check…Capabilities` 5종)를 확인하고 원래 값을 읽는다: 앰비언트 밝기·색·스위치(영역별), 실내등 스위치, 독서등 스위치(좌석별). 좌석 목록은 enum이 아니라 capability 콜백의 Map 키에서 얻는다.
- 앰비언트는 원래 값을 읽은 영역만 바꾸고, 실내등·독서등은 capability 가 돌려준 스위치 값만 보낸다. 읽은 항목마다 되돌리는 동작을 복원 목록에 넣는다. 종료할 때 목록을 전부 실행한 뒤에 SDK를 해제한다(먼저 해제하면 되돌리는 set이 버려진다). 순서는 앰비언트 → 실내등 → 독서등.
- 복원이 끝난 뒤 늦게 도착한 set은 `stopped` 가드로 막는다.
- **기어 D·R**: 종료(3초 뒤)보다 먼저 되돌린다. 그 사이 앱이 죽어도 조명은 원래대로다.
- **비정상 종료**: 읽은 원래 값을 `OriginalStore`(SharedPreferences)에 저장하고, 처음 바꿀 때 dirty 로 표시하고, 복원을 마치면 지운다. 다음 실행이 dirty 를 보면 저장된 값을 원래 값으로 채택하고 다른 값은 즉시 되돌린다.
- 남은 한계: 비정상 종료 뒤 다음 실행이 없으면 조명은 스튜디오 값으로 남는다.
- 앰비언트·실내등·독서등의 바깥 변경은 리스너(`register…Listener`, `register…State`)로 따라간다. 실내등·독서등은 스위치 변경 리스너가 없어 상태(켜짐/꺼짐) 리스너로 근사하므로, 바깥에서 AUTOMATIC 으로 바꾸면 ON 으로 보일 수 있다.

### 3.3 조명 값의 기준

- 차와 폰이 같은 값을 들고, **마지막으로 바뀐 쪽(`ts`가 큰 쪽)** 이 기준이다. 같은 시각이면 폰, 기본값(`ts` 0)은 항상 진다(`LightingParams.supersedes`).
- 기기 간 시계 차이는 HELLO 의 `now` 로 받는 쪽 시계에 맞춰 보정한다.
- 내 값이 바뀌면 150ms 디바운스 뒤 보낸다. 상대에게서 온 값은 되돌려 보내지 않는다(에코 없음).
- 되돌려 보내지 않는 것은 받은 값이 그대로 돌아오는 그 한 번뿐이다. 받은 값과 다른 값을 보낸 뒤에는 받은 값을 잊는다(`EchoGuard`, 조명 값과 앱 상태 모두). 잊지 않으면 A(폰에서 받음) → B → A 로 돌아왔을 때 마지막 A 를 보내지 않아 폰이 B 에 남는다.
- 동시 조작 충돌은 따로 풀지 않는다. 마지막에 받은 최신 값을 적용한다.
- 양쪽 다 사용자가 바꾼 마지막 값을 저장해 다음 실행에 이어 쓴다.
- 앰비언트 연동이 켜져 있으면 차는 같은 색·밝기를 앰비언트에도 넣는다(원래 값을 읽은 영역만).

### 3.4 앱 상태와 프리셋

- 스튜디오 앱 상태(앰비언트 연동, 풀 라이트, 다이얼 대상, 차 화면 테마, 사용자 프리셋 목록)는 **차가 기준**이고 폰에서도 바꿀 수 있다(STATE). 폰에 차량 제어를 직접 넣지 않는다.
- 차가 떨어져 있으면 폰의 '차 화면' 구역은 잠기고, 프리셋은 고르기만 된다(저장·삭제 불가).
- 실행마다 기본값으로 돌아가는 것: 풀 라이트, 다이얼 대상, 앰비언트 연동. 다음 실행에 이어지는 것: 차 화면 테마, 사용자 프리셋, 마지막 조명 값.
- 프리셋은 링라이트(색온도 또는 무드 색, 밝기)와 앰비언트 연동을 한 번에 정한다. 기본 4종:

| id | 이름 | 색 | 밝기 |
|---|---|---|---|
| `daily` | 데일리 | 7000K | 70% |
| `warm` | 웜 뷰티 | 3200K | 85% |
| `cool` | 쿨 시네마 | 8000K | 45% |
| `neon` | 네온 | 퍼플 | 60% |

- **기본 프리셋**을 적용하면 차가 실내등·독서등을 끈다(머리 위 그림자). **사용자 프리셋**은 실내등·독서등을 건드리지 않는다. 실내등·독서등은 패널에서 직접 만지지 않고 프리셋으로만 바뀐다.
- 사용자 프리셋은 지금 값으로 만든다(id `user-<만든 시각>`, 이름 "내 프리셋 N"). 저장·삭제는 차가 하고, 폰은 COMMAND 로 부탁한다. 기본 프리셋은 지울 수 없다.
- 폰에서 프리셋을 골라도 차가 처리하므로(`scene.apply`) 실내등·독서등까지 같은 결과가 된다.

### 3.5 미러링

- 폰 앱은 카메라를 잡지 않는다. `MediaProjection`으로 화면을 캡처해 포그라운드 서비스(`mediaProjection` 타입)에서 보낸다. 액티비티가 죽어도 송출은 유지된다.
- 가상 디스플레이는 정사각형(한 변 1200px) 하나를 한 번만 만들고, 화면이 들어간 영역만 잘라(`MirrorFit`) 보낸다. 회전하면 영역만 다시 계산한다(세로 540×1200 ↔ 가로 1200×540).
- JPEG 품질 60, 15fps 상한, 쓰는 중이면 건너뛰어 최신 프레임만 보낸다. 차는 전용 스레드에서 디코드하고 최신 프레임만 그린다.
- 화면 공유 동의는 세션마다 받는다(Android 14+ 는 토큰이 1회용). 기본 안내는 **"앱 하나만 공유"**: 고른 촬영 앱 화면만 차에 보이고 알림·다른 앱·플로팅 컨트롤은 비치지 않는다. 어느 쪽인지는 시스템 동의 화면에서 사용자가 고르며 앱이 강제할 수 없다.
- "앱 하나만 공유"에서 그 앱이 가려지면 검은 프레임이 오고, 그 앱이 종료되면 공유도 끝난다. 폰이 STATUS 로 알리고 차가 이유를 띄운다. 공유가 끝나면 폰에 "화면 공유가 끝났어요" 알림이 뜨고 탭하면 바로 동의 화면으로 간다.
- `FLAG_SECURE`를 건 앱(DRM·금융)은 검게 캡처된다.

### 3.6 폰 찾기

차는 사용 가능한 동안 아래 순서로 폰을 찾아 접속하고, 못 열거나 끊기면 2초 뒤 다시 시도한다(`PhoneLink`, `PhoneAddress`).

1. USB 액세서리(AOA): 차가 USB 호스트로 폰을 연다.
2. USB 테더링: 차가 폰의 USB 네트워크에 붙어 있으면 그 기본 경로의 게이트웨이가 폰이다.
3. 무선(NSD): 같은 Wi-Fi 또는 폰 핫스팟에서 폰 앱이 광고하는 `_selene._tcp`를 2초 동안 찾는다.
4. 데모 고정값: `10.0.2.2:8080`(에뮬레이터에서 본 Mac).

1~3은 실차·실기기가 있어야 확인된다. 지금까지 확인한 것은 4뿐이다.

### 3.7 다이얼

- car-ui-lib 의 `FocusParkingView` + `FocusArea` 안에 포커스 대상 뷰 하나(`DialTarget`)를 두고 회전(`ACTION_SCROLL_FORWARD/BACKWARD`)을 받는다.
- 회전 1칸은 밝기 5% 또는 색온도 250K. 대상은 패널·폰의 "다이얼" 분할 버튼으로 바꾼다(STATE `dialColor`).
- 다이얼 누름·nudge 는 RotaryService 가 가져가서 앱에 오지 않는다. 그래서 누름으로 대상을 바꾸지 않는다.
- 터치 뒤 첫 회전 1칸은 포커스 복구에 쓰인다.
- 다이얼은 조명 전용이다. 폰 조작은 폰에서 한다.

### 3.8 화면·테마

- 색·글자 크기·칩·슬라이더·상태 표시·조명 값 문구는 `poc/ui`(`StudioTheme`, `StudioColors`, `LightLabels`, 공용 컴포넌트)를 쓴다. 차 패널과 폰 화면에 같이 나오는 구역(링라이트·프리셋·색·차 화면)은 구역 컴포넌트 하나를 양쪽이 쓴다.
- 구역 순서는 자주 쓰는 것부터이고 차와 폰이 같다: 링라이트(지금 값·밝기) → 프리셋 → 색(색상환·흰 빛 톤 칩. 헥사 입력은 폰에만 둔다) → 차 화면(다이얼 대상·앰비언트 연동·풀 라이트·테마).
- 차 화면 배치(`PanelLayout`): 바깥이 링라이트이고 테두리 두께가 밝기를 따른다(8~80dp). 안쪽 내용은 테두리가 가장 두꺼울 때를 기준으로 자리를 고정해, 밝기를 바꿔도 모니터와 패널이 움직이지 않는다.
- 세로 영상이거나 영상이 아직 없으면 모니터를 가운데 두고 조명 패널을 양옆 두 칸으로 나눈다(왼쪽: 링라이트·프리셋, 오른쪽: 색·차 화면). Pleos 에뮬레이터의 앱 영역(1680×1208dp)에서 스크롤 없이 다 보인다. 가로·정사각 영상이거나 앱 영역이 좁으면 모니터를 넓게 쓰고 패널은 오른쪽 한 칸에 이어 붙인다(넘치면 스크롤되고 아래 끝을 흐리게 해 알린다).
- 풀 라이트는 차에서 패널 맨 아래에 늘 보이는 버튼이다(폰에서는 켜짐·꺼짐이 보이는 스위치). 풀 라이트 화면의 안내는 들어올 때와 다이얼로 값을 바꿀 때 4초만 뜬다.
- 누르는 것의 최소 높이는 `StudioSizes.Touch`(차 64dp, 폰 48dp)이고 스위치는 줄 전체가 눌린다. 차 글자는 18sp 아래로 내리지 않는다.
- 앱 아이콘은 초승달이고 두 앱이 `poc/ui` 의 같은 리소스(`ic_selene`)를 쓴다.
- 차는 실내 마감에 맞춘 어두운 저채도 세트(`CarThemes`: 블랙·웜 그레이지·네이비)만 쓰고 밝은 테마를 두지 않는다(차 화면 자체가 조명). 폰은 시스템 설정을 따르는 라이트·다크.
- 채도 있는 색은 실제 조명 색과 상태 표시에만 쓴다.
- 차량 앱은 앱이 앞에 있는 동안 창의 화면 밝기를 최대로 올리고(`screenBrightness = 1f`) 벗어나면 되돌린다. 실차 허용 여부는 확인 항목이다.

## 5. 확인한 사실

- Vehicle SDK 2.3.2 바이너리: `LightSwitch` = `OFF, ON, DAYTIME_RUNNING, AUTOMATIC`, `LightState` = `OFF, ON, DAYTIME_RUNNING`. `SeatArea`는 `Area`를 상속한 클래스(enum 아님)라 좌석 목록은 capability 콜백에서 얻는다.
- 실내등·독서등 함수는 문서대로 바이너리에 있다: `get/setCabinLightSwitch`, `get/setReadingLightSwitch(area)`, `getCurrentCabinLightState`, `getCurrentReadingLightState(area)`, `registerCabinLightState`, `registerReadingLightState(area)`.
- 조명 set 은 SDK 어노테이션에 `CAR_LIGHTS`만 적혀 있지만 런타임은 `CONTROL_CAR_LIGHTS`를 요구한다(에뮬레이터 2.1.0). Playground 의 Vehicle Control 은 "준비 중".
- Virtual Console Convenience 도메인에 실내등·독서등 항목이 있다([../contest/environment.md](../contest/environment.md)).
- 에뮬레이터 2.1.0 에서 앰비언트 밝기·색 set 은 Virtual Console 의 `body.ambient_light`(mode·color·brightness_pct)에 그대로 반영되는데, SDK 로 읽은 앰비언트 스위치는 그때도 OFF 다(2026-11-13). 그래서 스위치 값은 화면에 쓰지 않는다.
- Virtual Console 의 `GET /vehicle/state` 는 세션(`POST /browser/session`)을 막 깨운 직후에는 묵은 값을 준다. 세션을 보내고 1초쯤 뒤에 읽는다.
- Pleos는 P에서 앱을 보여 주고, D·N에서는 DO 미선언 앱을 가린다.
- Pleos 문서(~130쪽 가이드)에서 USB 언급은 Android Auto(AOAP/USB) 용어 설명 하나뿐이다. 서드파티 앱의 USB 사용 여부는 문서에 없다.
- API 37 에뮬레이터의 화면 공유 동의 화면은 "Share one app"이 기본 선택이고, 앱 목록에서 고른다.
- 폰 에뮬레이터 기본 AVD(Medium_Phone)는 CPU 1코어라 송출이 1fps 로 나온다. `-cores 4` 로 띄우면 홈 1~2fps(바뀔 때만), 스톱워치 7~8fps, 카메라 프리뷰 4~6fps. 해상도·품질을 낮춰도 fps 가 같아 병목은 에뮬레이터의 가상 디스플레이 합성·GPU 버퍼 읽기와 카메라 HAL 경쟁이다.
- 코덱 벤치(540×1200): JPEG q60 인코드 8~15ms·디코드 3~6ms, 소프트웨어 H.264 인코드 30~35ms·디코드 8~9ms, 크기는 H.264 가 10배 작다. 두 에뮬레이터 모두 인코더는 소프트웨어(`c2.android.avc.encoder`)뿐이다.
- 수치와 방법은 [../poc/verification.md](../poc/verification.md).
